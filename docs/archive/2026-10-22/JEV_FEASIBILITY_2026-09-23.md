# Jev 引入可行性调研

调研日期：2026-09-23（上海时间）。对象为 TypeSafe AI 的 Jev；范围为当前 quant A 股研究与 Paper 项目。依据为官方文档、现有代码、归档输入与已有真实调用回执。本次没有调用 Jev，因此下文的改善幅度是待验证判断，不是实测性能或收益承诺。

**结论：技术上可接入，当前整体价值偏小。最值得验证的是研究线索的语义分类，其次是新闻相关性和事件分类；暂不建议替换七角色研究、风控审批或交易决策。先完成现有真实闭环，比立即接入新模型更有价值。**

| 环节 | 预期作用 | 判断依据与边界 |
| --- | --- | --- |
| 研究线索分类 | 局部可能有中等改善；整体量小 | 当前依靠关键词。Jev 有机会区分策略机制、概念介绍、失效警示与无关内容，但中文准确率尚未验证 |

**模型事实与证据强度**

Jev 的接口接受状态和预先定义的问题，返回 Choice（类别）、Score（等级评分）、Noul（判断为真的概率）；它不生成自由文本。同一次请求中的问题分别判断，业务上的依赖和组合由代码处理。[官方介绍](https://docs.typesafe.ai/introduction)

官方模型页当前列出 `jev-1.13.0`，输入价为每百万 token 0.042 美元，输出免费；英文是表现最好的主要训练语言，中文需要自行验证。版本别名会移动，试验应固定版本。[模型与价格](https://docs.typesafe.ai/models)

官方发布于 2026-09-15 的文章称产品处于 early access，公布的 70–500 ms 为厂商数据，测试主要在美国西海岸完成，不可当成本项目网络下的延迟。[发布说明](https://typesafe.ai/blog/introducing-system-one-models-and-jev)

“零幻觉”应理解为厂商声称的输出类型约束，不能推导成事实或判断正确。官方已披露数值精度、日期比较、多跳推理、无关长上下文及对抗文本等弱点。[已知限制](https://docs.typesafe.ai/model-jaggedness/jev-1.13)

`confidence` 是概率分布的统计量，不是独立验证出的正确率，也不是上涨概率；不同问题及 Choice/Noul 之间不能直接搬用阈值。[置信度说明](https://docs.typesafe.ai/confidence)

公开官方评测覆盖安全事件、Agent 轨迹、发票和客服，参考标签来自强模型响应的共识。这是工作流评测，不能证明中文金融判断、A 股 alpha 或未来收益。本次未取得相应中文金融人工标注基准或本项目 Jev 实测结果。[官方评测方法](https://evals.typesafe.ai/)

**项目里的具体切口**

1. **研究线索分类最适合先试。** [research_ingest.py](/Users/henry/projects/quant/pipeline/research_ingest.py:72) 的 `classify_item` 和 `pick_template` 按词匹配。只读调用当前纯分类函数，对两个明确标注为人工构造的案例得到：

   | 人工构造的输入 | 当前结果 |
   | --- | --- |
   | “动量策略已经失效”；“本文只有风险警示，不提供交易规则。” | `trading_signal` / `momentum` |
   | “动量策略入门”；“仅介绍概念，没有股票池、买卖条件和交易成本。” | `trading_signal` / `momentum` |

   这说明现有类别无法单靠词命中确认“存在可实现机制”，不是一次真实盈利策略漏判测试，也没有证明 Jev 一定答对。适合增加的候选判断是：是否给出明确交易条件、是否仅概念介绍、是否提供失效证据、是否具有 A 股适用性。应保留有价值的失效研究，不能简单当噪音丢弃。即使分类改善，也只用于线索排序，不自动生成或晋级策略。

2. **新闻量不足以支撑强烈的降本诉求。** [collect.py](/Users/henry/projects/quant/trading_team/collect.py:314) 默认拉取 30 条快讯并把摘要截到 200 字符；9 月 21、22 日现有 `news.json` 各为 10 条。另有 `global_macro.json` 等输入，不能把这 10 条当成全部信息源。本地监控报告有 16 个日期文件、合计 92 条记录，未做跨日去重，也不等于每天连续运行。Jev 无法恢复未采集或被截断的信息；先保证来源、时间和完整性更重要。

3. **最耗 token 的部分不是新闻分类。** 读取 [9 月 23 日隔离发布验收回执](/Users/henry/projects/quant/docs/audits/2026-09-23-real-publication-recovery.json)，七次成功请求输入合计 121,590 token、输出 23,749 token。其中新闻角色输入 6,313 token，约占输入的 5.2%；技术分析输入 45,844 token，约占 37.7%。这是一次成功请求样本，不包含中断请求的未知费用，也不是月均账单。新闻过滤不能消除新闻报告的解释任务，更不能据此按 Jev 单价替换全部七次调用费用。技术输入裁剪值得单独测量，但本次没有修改它。

4. **当前仍以打通真实闭环为优先。** 上述回执是隔离 `publication_only` 成功，`business_complete=false`、`reviews=not_checked`；[真实闭环计划](/Users/henry/projects/quant/docs/REAL_CHAIN_ROLLOUT.md) 仍保留独立审阅、唯一入口及自然交易日验收。这里引用本次读取的本地证据快照，未重新审计远端运行。新增模型不能补齐这些业务完成证据。

**接入难度与净收益**

现有 [KimiClient](/Users/henry/projects/quant/trading_team/kimi_daily.py:214) 使用 `/chat/completions`，角色执行器必须取得 `report_markdown`。Jev 使用 `/v1/systemone` 的 `state/questions/answers` 协议，不能通过修改模型名称直接替换。[官方 API](https://docs.typesafe.ai/api)

若做试验，最小方案是独立分类适配器，复用项目已有 HTTP 库；原研究执行器继续运行。新增适配器要保存输入哈希、题目与评分标准版本、实际模型版本、概率、耗时、usage 和失败原因。只有通过评价后，才考虑把分类结果作为额外证据输入；不能把 Jev 输出伪装成现有七角色回执。

在“每条 1,000 输入 token、每月 22 天”的假设下，按上述官方单价：

| 每日处理条数 | Jev 月输入费用估算 |
| --- | ---: |
| 10 | 0.00924 美元 |
| 30 | 0.02772 美元 |
| 1,000 | 0.924 美元 |

这是算术估算，不是实际账单；不包含回退大模型、重复请求、接入维护、标注与可能的网关费用。现有关键词函数本身无模型调用费，因此替换关键词不等于省钱。净收益必须来自误筛减少或后续研究工作减少。

接入仍需取得可用访问权限，并实测本地网络、限流与失败行为。初测只需公开新闻与去敏线索；不需要提交账户、审批或私有持仓。官方“不用于训练”与“零保留”是不同承诺，ZDR 单独面向企业客户。[数据政策入口](https://docs.typesafe.ai/legal)

**建议的最小验证与停止条件**

建议只验证“研究线索分类/新闻相关性”一个任务，先旁路记录，不改变正式报告、审批和 Paper：

1. 从归档建立去重中文样本，加入否定、反讽、失效研究、旧闻重发及风险事件。当前线索只有 92 条原始记录；首轮可用于可行性排查，正式比较再积累约 300–500 条，经人工复核标签，并按时间和事件分组留出测试集。这个规模只适合初筛，不证明罕见风险事件可靠性。
2. 同输入比较三种方案：当前关键词规则、现有 Kimi 的短结构化分类、固定版本 Jev。先把任务拆成原子问题；此项工程改进也可能让现有模型变好，不能把全部改善归给 Jev。
3. 评价关键内容召回、误筛率、macro-F1、概率校准、转交比例、端到端耗时和含回退的费用。未知或失败转给原流程；试验期不自动删除任何风险新闻。测试集只评价，不用于反复改提示词。
4. 建议采纳线：相同关键内容召回下误筛率有稳定改善，或质量不下降时端到端费用/耗时下降至少 20%。20% 是建议的工程验收目标，不是预测收益；必须同时报告样本量、不确定性和绝对节省金额。仅因 API 很便宜或单条响应快，不算通过。
5. 若中文效果不优于规则/现有 Kimi、回退占比高、节省金额小于维护投入，停止接入。若未来要把分数用于交易，另建冻结版本的前向 Paper 对照，纳入可用时点、交易约束、费用、风险暴露和样本不确定性；不能把分类实验成绩当成收益证据。

**最终建议：保留 Jev 为低优先级研究候选。可以做有限的旁路分类对照；现阶段不应为它改造主研究框架，不应期待它解决当前执行故障或直接提升投资收益。**
