## 来源契约

新生成回执使用 `daily_research.v4`，包含 `model_transport.v1`。例如离线验收记录：

```json
{
  "schema": "model_transport.v1",
  "adapter": "offline_fixture.v1",
  "endpoint": "https://fixture.invalid/v1",
  "model": "offline-test",
  "parameters": {
    "temperature": 0.6,
    "max_tokens": 8192,
    "thinking": "disabled",
    "response_format": "json_object"
  }
}
```

- 当前 HTTP 客户端的适配器为 `openai_chat_completions.v1`，不再硬编码服务商为 Moonshot。
- 请求模型、实际服务地址和参数进入角色缓存指纹、角色回执、实际请求记录及发布回执。
- 每个角色调用前先持久化请求意图；调用后核对实际请求来源，运行途中变更来源禁止发布。
- 服务返回的模型标签单独记为 `reported_model`。这是服务端声明，不是模型权重、计费账户或判断质量的独立认证。
- 来源中不保存 API Key、密钥哈希或认证头。同地址、同模型、同参数下换 Key 不改变缓存身份；这不等于已经启用额度自动切换。
- URL 禁止用户名、密码、查询参数和片段，错误不回显这些内容；HTTP 不跟随重定向，非 200 响应不能认证为原服务的成功请求。

## 重试与旧记录

普通重试仅复用来源、输入、角色章程、报告及结构化响应哈希一致的产物。
已发布报告或部分暂存报告的来源变化时，停止并要求显式重新生成，不自动覆盖。
现有 `--force` 路径将旧暂存目录归档；新报告发布时归档旧输出。它会重新调用模型、
可能产生费用和新计划版本，不是只读修复命令，也不会替用户批准计划。

旧 `daily_research.v3` 或没有来源字段的文件保留为旧证据，不能静默升级为 v4。
独立检查器在核对输入、输出、计划版本、风险契约和发布账本后，还会核对七个角色与实际请求来源一致。
不补造旧模型来源，不倒签旧审批。

交易员和风控的账户输入不再包含快照观察时间 `generated_at`，避免等待几秒就无意义地重跑。
现金、库存、保护版本、行情日期和其他业务事实仍留在输入及其哈希中；现金变化仍会使相关缓存失效。

## 原额度接入前提

本机 Kimi CLI 的 print 模式并不自动等于无工具的模型传输。只读源码检查发现认证刷新、
全局插件、MCP 和 Hook 等初始化路径；隔离运行目录还会改变凭据位置。
本轮未运行模型、读取或复制 OAuth 凭据、修改全局配置，也未用客户端身份伪装获取额度。

“先用之前的”仍需确认是项目原 API Key，还是 Kimi 桌面 / Kimi Code 会员额度。
Kimi Code 与开放平台 API 的认证和计费来源不能仅凭“API”二字判断，接入须遵守真实客户端身份要求。

[Print 模式](https://moonshotai.github.io/kimi-cli/en/customization/print-mode.html)、
[数据目录](https://moonshotai.github.io/kimi-cli/en/configuration/data-locations.html)。
这些文档不能证明本账户的权益、余额或项目当前使用的计费来源。
