# Paper 逐批库存

## 口径

`fifo_acquisition.v1` 从现有 `trades` 按成交编号顺序重建剩余买入批次，不新增一张可独立修改的库存表。
每批保存原成交编号、买入日期和剩余股数。`positions` 仍是数量、加权平均成本和最近买入日期的聚合投影。

批次只决定可卖数量和消耗顺序，FIFO 是本系统的可复现记账约定，不是交易所指定的成本核算方式。
加权平均成本保持不变；不把分批买入成本改成 FIFO 成本，也不重新计算历史盈亏。

一般 A 股的当日买入限制针对未交收买入，而非把同标的旧仓一并冻结；回转交易品种有例外。
依据为[上交所交易规则（2026年修订）第3.1.4、3.1.5条](https://www.sse.com.cn/lawandrules/sselawsrules2025/stocks/exchange/c/c_20260424_10816482.shtml)。
本模块沿用项目普通 A 股日线模型，不扩展到特殊回转交易品种。日期计算必须配合公开入口的
交易日历和已完成会话校验；显示可卖量不是交易所接单、交收完成或实盘执行授权。

## 执行规则

- 早于查询/执行日买入的剩余批次计入可卖量，当日买入计入冻结量。
- 例如旧仓500股、当日加仓400股：合计900股，可卖500股，冻结400股。
- 部分减持必须是小于总持仓的整手固定数量，并且不超过可卖量。
- 全卖 `qty="all"` 仍指全部持仓；含冻结股时整单拒绝，绝不静默缩为可卖数量。
- 卖出从最早可卖批次扣减；未触价、停牌、涨跌停拒绝或其他未成交结果不消耗批次。
- 非法股数、未知方向、重复/倒序成交、日期异常、超卖或聚合数量/最近买入日不一致时拒绝构造可信库存。
- 新结算前必须重建并匹配期初库存；同日已存在成交却没有结算回执时拒绝继续，不当作期初批次。

低层单日诊断仍允许显式提供单一买入日期的假设期初仓位，属于输入假设，不能赋予数据库账户可卖权限。
双 Paper、旧 LLM Paper 执行入口、连续反事实都从各自成交账本核对库存，没有补签或迁移生产历史。

## 证据与恢复

新执行回执记录 `inventory_policy`、`inventory_basis` 和 `inventory_closing`，包含批次投影和成交数量账本哈希。
哈希绑定成交编号、日期、代码、方向和股数；价格、费用及现金一致性仍由原账户审计检查。
不把数量重建称为完整成交认证，`execution_certified` 保持 false。

复跑核对当日期初/期末批次以及当前聚合库存。日常收尾的缓存复核调用同一检查，不能因为
当日订单没变就忽略早前成交或现持仓被改动。合法后续交易不会改变旧日的期初/期末证据。
批次派生失败发生在提交前时，成交、持仓、估值和回执一起回滚。
原有 SQLite 备份已包含完整成交账本，无需新增库存迁移。恢复后先核验，不能直接激活生产。

旧回执没有新库存政策时保留旧事实并标记未认证；不能把当前能重建的数量当作旧撮合规则已正确执行。
FIFO 数量匹配也不能补足旧计划、风险、审批、价格或发布时间证据。

## 查看

控制台“交易台”显示每个标的可卖/冻结数量，可展开查看成交编号、日期和剩余股数。
缺证时显示“未知”，不再显示成零冻结或全部可卖。角色输入、交易员与风控提示词使用同一边界。

```bash
curl --fail http://127.0.0.1:7100/api/paper-state
.venv/bin/python -m trading_team.paper_reconcile
.venv/bin/python -m pytest tests/test_paper_inventory.py tests/test_paper_reconcile.py tests/test_finalize_recovery.py -q
```

上述两个读取入口不结算、不发送模型请求、不通知或批复。历史审计可能以非零退出码报告原有缺证/冲突。
