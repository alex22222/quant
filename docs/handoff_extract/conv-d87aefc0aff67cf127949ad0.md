## 二、建议的执行路径（约 8–12 周）

**第 0 步：书单先行（1 周，与后续并行）**
扫一遍 awesome-quant 目录建立地图；精读 machine-learning-for-trading 的前 3 章，理解「数据→因子→回测→执行」全链路。

**第 1 阶段：数据层（1–2 周）**
- 用 **akshare** 拉 A股/港股日线、分钟线、财务数据，落地到本地 SQLite/DuckDB（你在 polymtrade 已有这个模式，直接复用）
- 美股用 yfinance / QuantConnect 数据源
- 产出：一个自己的三市统一数据管道 + 增量更新脚本

**第 2 阶段：回测引擎入门（2 周）**
- 用 **backtesting.py** 写 3 个经典策略（双均线、布林回归、动量轮动），在美股 SPY、港股恒指 ETF、A股沪深300 ETF 上各跑一遍
- 用 **quantstats** 输出统一绩效报告，建立评价基准（夏普、最大回撤、Calmar）

**第 3 阶段：因子与 ML 研究（3–4 周）**
- 进入 **qlib**：用它自带的 A股 Alpha158 因子集，跑通 LightGBM 排序模型 → TopK 选股回测
- 用 **vectorbt** 做参数网格扫描，理解过拟合与样本外验证
- 这阶段是你「研究」的主战场，目标是产出第一个有样本外正收益的多因子策略

**第 4 阶段：工程化与模拟盘（2–3 周）**
- A股：研究 **vnpy** 或 **rqalpha** 的模拟盘接入（rqalpha 更轻，vnpy 更全）
- 把第 3 阶段的策略改造成每日定时信号 → 模拟盘执行 → 绩效跟踪闭环（参考你 stockconsult 的 Loop Engineering 思路，加准确率反馈回路）

**可选进阶**：wondertrader（高频/CTA）、FinRL（强化学习）、FinGPT 类 LLM 方向。

## 三、给你的取舍建议

- 已有 polymtrade 的 Python + SQLite + 数据管道经验，**第 1 阶段几乎免费**，重点投入第 3 阶段（qlib 因子研究），这是三市量化里投入产出比最高的切入点
- 别一开始啃 vnpy 源码——它是工程框架不是研究工具，研究效率低
- backtrader 只读文档和示例学思想，不要作为主力引擎（停止维护多年）

## 一、先说结论

**Mac 上没有原生可用的 A 股券商交易终端**，这是行业现状：QMT、PTrade、掘金等客户端全部 Windows Only，根源是券商柜台协议栈和合规要求绑死了 Windows 生态。但 Mac 用户有 **5 条可行路径**，按推荐度排序：

1. **PTrade 云端托管**（最省事，Mac 只写代码，策略跑券商机房）
2. **Parallels/VMware 虚拟机跑 miniQMT**（本地实盘最主流方案）
3. **桥接模式**：Windows 机器/云服务器做网关，Mac 通过 HTTP API 调用（架构最优雅，适合你现有的 polymtrade 技术栈）
4. **中泰 XTP**（唯一原生支持 Mac 编译的券商级 API，但门槛 300 万 + 专业投资者认证）
5. **easytrader 模拟点击**（无门槛但脆弱，仅适合过渡）

## 二、合规背景（先懂规则再选工具）

- A 股程序化交易必须**报备**：向券商申报策略基本信息，券商报交易所。2025 年 7 月起沪深北《程序化交易管理实施细则》生效，高频认定线约每秒 300 笔/单日 2 万笔申报，超出有额外监管和收费。
- 这就是为什么券商不开放裸 API 给散户——监管红线是杜绝场外配资，所有程序化通道必须是"券商提供的终端"。你能选的都是**终端形态**而非纯 API（XTP 除外，它有托管合规流程）。

## 三、五大方案详解

### 方案 1：恒生 PTrade —— Mac 友好度最高

- **架构**：策略上传到券商内网云端 7×24 运行，本地客户端只负责写代码/看日志。写完策略关掉 Mac 都不影响执行。
- **Mac 使用方式**：客户端是 Windows 的，但可以装在虚拟机里**只做开发**，策略上传云端后完全脱离本地环境。部分流程甚至可以手机 APP 监控。
- **门槛**：券商差异大，国金、华宝等约 10 万资产；银河、华泰等 30–50 万。开通免费，佣金与普通账户一致。
- **限制**：云端沙箱**禁止外网访问、禁止 pip install**、只能用白名单库（Pandas/Numpy/Talib），不能读本地 CSV——你的外部数据融合、ML 模型推理做不了；无 Tick 逐笔回测，实盘最小 3 秒粒度。
- **适合**：日线/分钟级中低频策略、网格、ETF 轮动，追求省心稳定。

### 方案 2：QMT / miniQMT —— 能力最强但绑死 Windows

- **架构**：迅投出品，本地终端 + `xtquant` Python 包（`xtdata` 行情 + `xttrader` 交易）。策略完全本地运行，可自由接 sklearn/PyTorch/外部数据源，毫秒级下单，支持股票/ETF/转债/两融/期权。
- **⚠️ 2026 年重要变化**：据 miniQMT.com 公告，**有券商自 2026-07-06 起停止 miniQMT 新申请**，存量用户暂可用但后续可能逐步收紧，建议迁移到标准 QMT。开通前务必向目标券商确认 miniQMT 是否还能开。
- **门槛**：10–50 万资产（券商差异大），免费开通。
- **Mac 打通的三种姿势**：
  - **Parallels Desktop 虚拟机**（M 系列芯片装 Windows 11 ARM，miniQMT 可正常运行；Intel Mac 直接 Boot Camp）
  - **桥接模式**：一台 Windows（或 Windows 云服务器）常驻运行 miniQMT，把 xtdata/xttrader 封装成 HTTP/gRPC 服务，Mac 端 Python 远程调用，数据自动写入 Mac 本地 DuckDB——**这是和你现有系统最契合的架构**
  - **纯云服务器**：阿里云/腾讯云 Windows Server 轻量实例（约 60–100 元/月）7×24 挂机，Mac 远程桌面管理
- **适合**：中高频、复杂自研策略、需要本地 ML 推理的用户。**你属于这类。**

### 方案 3：中泰 XTP —— 唯一原生支持 Mac 的券商 API

- 极速柜台（类 CTP 接口设计），官方 SDK 支持 Windows/Linux，**中泰官方明确表示是"唯一可以接口苹果"的券商柜台**，Mac 下可自行编译（GitHub 有官方 `xtp_api_java` 等开源封装，mac 需自行编译调试 `.dylib`）。Python 可经 vnpy 的 `vnpy_xtp` 网关接入。
- **门槛极高**：专业投资者认证（自然人 **300 万金融资产** + 1 年投资经历）+ "三方采购"流程（券商安全审查你的程序并签采购协议）+ 实盘程序必须托管在券商内网服务器，禁止向外网发送行情交易数据。
- **适合**：资金量达标、追求极致速度、愿意走合规流程的用户。对大多数个人不现实。

### 方案 4：easytrader / 客户端模拟 —— 无门槛过渡方案

- GitHub 开源（配合 easyquotation），通过模拟操作同花顺/银河/华泰等客户端下单，支持跟踪雪球组合调仓。
- **问题**：依赖客户端 UI 结构，券商客户端一升级就挂；无法获取回报确认；合规灰色地带。仅适合策略验证期、小资金、低频。

### 方案 5：曲线救国 —— 港美股通道

如果研究范围含港美股，**富途 OpenAPI（futu-api-doc）和盈透 IBKR API 都原生支持 Mac**，合规且免费（富途需对应市场权限）。很多人用 Mac 跑港美股量化 + 虚拟机跑 A 股 QMT 的混合架构。

## 四、给你的推荐执行路径

结合你已有 Python + SQLite/DuckDB + 数据管道的底子：

1. **第 1 步（本周）**：选券商开通量化权限。优先问客户经理三个问题：① miniQMT 还能不能新申请（2026 收紧中）② 资金门槛 ③ 是否支持 PTrade。**建议 QMT + PTrade 双开**（很多券商两者都送），互为备份。
2. **第 2 步**：Mac 装 Parallels + Windows 11 ARM，装 QMT，先用内置环境跑通 hello world 策略和模拟盘。
3. **第 3 步**：搭桥接架构——Windows 虚拟机常驻跑 miniQMT，你写一个 FastAPI 网关封装 xtdata/xttrader，Mac 主程序（你的 qlib 研究环境、Dashboard）通过局域网调用。这样研究和回测留在 Mac 原生环境，执行走网关。
4. **第 4 步**：低频策略跑顺后，若需要无人值守，把策略迁到 PTrade 云端（接受其沙箱限制）或把 miniQMT 迁到 Windows 云服务器。
5. **风控闭环**：沿用你 stockconsult 的 Loop Engineering 思路——委托回报校验、断线重连告警、每日对账推送飞书。

## 五、关键风险提示

- miniQMT 政策正在收紧（2026-07 起部分券商停新申请），**不要把架构绑死在 miniQMT 上**，桥接网关层做好抽象，底层可换 QMT 标准版/PTrade。
- PTrade 云端沙箱限制决定了它做不了你 polymtrade 那种"外部数据 + 模型推理"的玩法，两者定位互补不冲突。
- 任何"免报备裸 API""破解协议直连柜台"的第三方服务都不要碰，账户被限制交易的案例不少。
