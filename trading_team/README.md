# HQCapital 交易团队 — 角色章程与工作纪律

> **公司名称**：HQCapital  
> **架构来源**：TradingAgents 多智能体 LLM 金融交易框架  
> **运行方式**：每日盘前自动召开晨会，依次扮演七角色流水线

---

## 角色边界速查表

| 角色 | 所属团队 | 职责定义（TradingAgents 原文） | 工作纪律（只能做什么） |
|------|---------|------------------------------|----------------------|
| 基本面分析师 | 分析师团队 | 分析财报、收益报告、内部交易等数据来评估公司内在价值，判断股票是否被低估或高估，为长期投资提供参考。 | 只输出基本面维度的研究报告，不替代情绪/新闻/技术分析师的职能，不参与多空辩论或交易决策。 |
| 情绪分析师 | 分析师团队 | 关注社交媒体、舆情打分以及公司内部情绪等公众信息，预测短期投资者行为可能对股价带来的影响。 | 只输出情绪维度的研究报告，不替代基本面/新闻/技术分析师的职能，不参与多空辩论或交易决策。 |
| 新闻分析师 | 分析师团队 | 追踪宏观经济指标、重大新闻及公司事件，识别对市场有潜在影响的突发消息或政策变化，为把握行情拐点提供依据。 | 只输出新闻维度的研究报告，不替代基本面/情绪/技术分析师的职能，不参与多空辩论或交易决策。 |
| 技术分析师 | 分析师团队 | 计算 MACD、RSI 等技术指标，分析价量关系和价格形态，判断买卖时机和趋势走势。 | 只输出技术维度的研究报告，不替代基本面/情绪/新闻分析师的职能，不参与多空辩论或交易决策。 |
| 研究员（多空辩论主持人） | 研究团队 | 阅读当日基本面、情绪、新闻、技术四份报告，组织「多头视角 vs 空头视角」辩论：找出共识、暴露分歧、评估证据强度，形成研究层面的综合判断。 | 只组织多空辩论与整合分析，不替代分析师的数据采集职能，不直接执行交易计划。 |
| 交易员 | 交易员代理 | 评估分析师及研究员的建议，决定交易时机与规模，执行买卖指令，动态调整持仓。 | 只将研究结论转化为可执行交易计划，不替代分析师的研究职能，不替代风险经理的风险审核职能。 |
| 风险经理 | 风险管理团队 | 评估市场波动、流动性、对手方风险等；执行风险缓释策略（止损、头寸分散）；向交易员提供风险反馈；确保整体组合与公司风险偏好匹配。 | 只审核风险敞口与下达调整建议，不替代交易员的交易决策职能，不替代分析师的研究职能。 |

**红线**：任何角色的产出不得越权替代其他角色的职能。

## 晨会流程

```
数据采集（collect.py）
    ↓
01 基本面分析师 → 02 情绪分析师 → 03 新闻分析师 → 04 技术分析师
    ↓
05 研究员（多头 vs 空头辩论）
    ↓
06 交易员（交易计划）
    ↓
07 风险经理（风险审核 + 组合预算）
    ↓
PM 审批（老板终审，pm_status=pending → approved/rejected）
    ↓
执行（如审批通过，手动录入 paper 台账）
```

## 数据入口纪律

LLM 角色的**唯一数据源**是 `briefing.py` 生成的晨会数据包。禁止 LLM 直接访问外部 API 或实时网络，所有数据必须经过确定性代码层采集、校验、归档后方可进入晨会流程。

## 团队纪律（LLM 局限性护栏）

> 依据：ChatGPT-quant 文的局限性清单——LLM 无实时数据、无法预测突发事件、存在数据偏见，结论必须交叉验证、不能替代风控。本节把散落在各 prompt 的护栏汇总成文，作为全员（人与 Agent）共同遵守的底线。

1. **数据缺口必须标注**：任何角色引用缺失/失败/过期的数据时，必须在报告中显式标注"数据缺口"，不得用猜测填补（采集 manifest 逐源记录 ok/fail，缺口随报告呈现）。
2. **事实与判断分离**：报告须区分"数据原文/计算结果"（事实）与"角色解读"（判断）；结论块中的评级是判断，不是事实。
3. **单角色结论不得单独成计划**：交易计划必须经研究员多空辩论整合后由交易员生成，再经风险经理审核；任何单一分析师的结论不能直接成为交易依据。
4. **准确率 <50% 降权**：`loops/accuracy.json` T+5 对照计分，角色评级准确率低于 50% 时在后续研究整合中自动降权。
5. **结构化结论块是唯一机器可读事实源**：各角色日报末尾的 ```json 结论块缺失或不合法时，该报告视为未完成（fail closed），自动化环节（accuracy 回填 / plan 富化）跳过而非猜测。
6. **先有假设再看结果（防 HARKing）**：禁止根据已见的回测/实盘结果倒推结论写进日报；策略侧由 `pipeline.promote --differentiation` 门禁与样本外验证强制执行，LLM 侧靠本纪律约束。
7. **LLM 输出是研究辅助，不是交易指令**：所有 LLM 产出（日报、辩论、计划）执行前**必须**经风控环节（07 风险经理 + 5 条不可协商条款）与**人工批复**（老板，批复台账 `loops/approvals.json`）；未经批复的提案永远停留在 `pm_status=pending`，任何自动化不得越级执行。
